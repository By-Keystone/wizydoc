Recorrido sugerido
  1. Escribe un correo y pulsa «Continuar». Si empieza con limite, sale el 429; si empieza con falla, el error del envío.
  2. Escribe 482913: al sexto dígito se envía solo. Cualquier otro código da el mensaje único; 000000 da el 429; con menos de 6, pulsa «Verificar código».
  3. Espera la cuenta (o enciende el reloj rápido) y pulsa «Reenviar código».
  4. «Cambiar» vuelve al correo. Con el mismo correo dentro del minuto, «Continuar» va directo al código sin pedir otro.
  5. Escribe la contraseña y pulsa «Crear cuenta», con el resultado elegido arriba.
Qué propone
  • Nunca conviven dos registros: el killswitch AUTH_BACKEND elige uno por entorno. Con better-auth, el de por defecto, estas pantallas responden 404.
  • Tenga o no cuenta el correo, se ve lo mismo. A quien ya tiene cuenta le llega otro correo, y el pie «¿Ya tienes cuenta?» lo lleva al login.
  • Un solo campo para el código, que se envía solo con el sexto dígito.
  • «Reenviar en N s» lo calcula el servidor, así que sigue contando aunque recargues. Un reenvío dentro del minuto no envía nada: la cuenta sigue, sin aviso.
  • El avance del registro dura una hora, más que el token (15 minutos): si el token vence, el correo sigue escrito.
  • Los mensajes de error son los de la spec de WIZ-75. Un código que no sirve muestra siempre el mismo.
  • Sin la casilla de los términos: vuelve cuando se publique la política de privacidad.
  • Igual para todos: no hay roles, ni 403, ni 402.
